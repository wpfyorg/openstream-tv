# Openstream TV Slim for Android

Native Android phone and Android TV front end for the OpenStream TV server, including the bundled web Settings UI. The APK carries one executable per ABI at `lib/<abi>/libopenstream_exec.so`. Android extracts it to `nativeLibraryDir`; the app runs it directly as a child process. No Termux installation is used.

## Build

Install Android Studio/SDK, Android NDK, Gradle 8.9+, `cargo-ndk`, and Rust with these targets:

```sh
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/<installed-version>"
./android/scripts/build-rust-binaries.sh
cd android
gradle assembleDebug
```

The helper builds the root crate with `--features full` so the bundled server can serve the Settings UI, and installs three Android executables into the app JNI library directories using the agreed filename. Set `ANDROID_API_LEVEL` to change the NDK linker API (default 23). The generated binary files are build inputs; they are not checked into source control. CI runs this helper before Gradle.

## Use

Open Openstream TV Slim and start the local server. It binds only to `127.0.0.1`, using port `5001` by default or the first free port through `5010` when another app already owns it. The selected port persists across restart and applies to playlist, login, and health requests; the app stores runtime state under its private files directory and sets `OPENSTREAM_PATH_PREFIX` for every CLI process. Choose **JioTV** or **JioTV+**, enter the matching account's mobile number, request an OTP, then enter the OTP yourself and verify. JioTV+ is enabled for the Android server process and uses the separate JioTV+ login endpoints; if a number has multiple eligible JioFiber/AirFiber connections, the app asks which connection should receive the OTP. OTP requests use the keyed route prefix obtained from `ost key show`. The app never puts the mobile number or OTP in its notification or process arguments.

Use **Provider settings** to open the bundled web Settings on the device. This is the full provider workflow: connect Fastway, PlayboxTV or VZY, and select the active provider with **Use …**. The native provider row only chooses the account used for OTP login; switching an already connected catalogue is done from **Provider settings**.

The app masks the access key in the displayed playlist URL. **Copy** and **Open in IPTV app** use the full URL. **Save M3U** downloads the actual playlist contents and writes the selected local file; it does not save the URL as text. The playlist contains loopback stream addresses, so playback needs the server running on the same Android device. The server is not exposed to the LAN. No LAN exposure control is included. On Android TV the dashboard combines server, startup, playlist, and configuration controls on the left, with provider selection and account login on the right. D-pad OK enters mobile/OTP text editing; Back exits editing. After Send OTP succeeds, the same button becomes Login, with a six-digit OTP field above it. The provider-specific **Log out** button is available only in the Android TV layout; the phone UI has no sign-out control.

Startup-screen permission has three setup options: Android's **Display over other apps** settings page, optional Shizuku, or **Set up using ADB**. They disappear after permission is granted; **Disable auto-start** separately turns off the boot preference without stopping the current server or revoking Android's permission. When enabled again, the app checks the actual permission. ADB setup uses a persistent key stored under the app's private no-backup directory and runs only `appops set org.opebstreamstv.android SYSTEM_ALERT_WINDOW allow`; it verifies the grant with Android and disconnects. The ADB button first tries `127.0.0.1:5555`, so a TV with classic TCP/network ADB already listening there can show Android's native debugging authorization prompt without typing an address or port. If that local endpoint is unavailable or Wireless Debugging pairing is required, the app opens the manual fallback with `127.0.0.1` and `5555` prefilled; on Android 11+ enter the Wireless Debugging pairing address/code and pairing port plus its separate debugging port as needed. The app never enables debugging itself. Approve Android's authorization prompt using the device controls. If debugging is off, enable it in Developer Options yourself first. Shizuku must be installed, running, and authorized when selected ([official download and setup](https://shizuku.rikka.app/)); non-root Shizuku started through ADB needs restarting after reboot. A stopped or unavailable Shizuku service does not affect the server. Neither setup method is needed for the server or boot receiver to start.

Use **Import TOML config** to select a TOML file. On Android 12L (API 32) and older, Android TV uses the app's built-in D-pad file browser, which starts in shared-storage Downloads and only shows folders plus `.toml` files; phones use Android's document picker when available and can fall back to the built-in browser. The built-in browser may request legacy shared-storage permission. On Android 13 (API 33) and newer, both TV and phone use Android's system document picker because legacy shared-storage permission no longer provides direct file access; if no system picker is available, the app reports that instead of opening the built-in browser. The app stages the selected file privately, validates it with the bundled executable and an isolated private data path, then atomically replaces the active config. A failed validation leaves the current config in place. Config content and command output are never displayed or logged. Stop and start the service to apply an imported config.

Use **Export TOML config** to save the current `config.toml`. On Android 12L (API 32) and older, Android TV uses the built-in browser to choose a shared-storage folder and phones use Android's document picker with the built-in browser as a fallback. On Android 13 (API 33) and newer, both TV and phone use Android's system create-document picker; if it is unavailable, the app reports the error and does not attempt direct shared-storage access. If no config exists yet, the app exports a valid TOML file containing the Rust runtime defaults. Export runs off the UI thread and does not include the separate login store or provider credentials.

Use **Import login store backup** separately to restore a `store_v4.toml` backup. The app validates the expected `[data]` store schema with the bundled executable while sending all command output to `/dev/null`. If the server is running, it waits for the service to stop before atomically replacing the store, then restarts it. A failed validation leaves the current login store unchanged. Store values are never displayed or logged. The Android provider row chooses the account used for OTP login; it does not switch an already connected catalogue, and the Android TV row is hidden after sign-in. Use **Provider settings** to switch the active provider and to connect Fastway, PlayboxTV, VZY or the Tata Play diagnostic tools.

## Service and limitations

Boot autostart is enabled by default. The boot receiver starts the foreground server independently of whether Android allows the app window to open. On Android 10 (API 29) and later, automatic UI launch requires the user-granted **Display over other apps** permission; otherwise open Openstream TV Slim from its notification. On earlier Android versions the receiver also attempts to open the app. **Start/Stop local server** changes the current service state only; **Enable/Disable auto-start** changes the persisted boot preference. The receiver waits for `BOOT_COMPLETED`, so startup occurs after user unlock.

The foreground service keeps the Rust server alive while Android runs the app's service. The dashboard polls server health, including unexpected exits, and shows red when stopped and green when started. Force-stopping the app or the OS terminating its process stops the server. Login requires Internet connectivity and a valid provider account. A URL containing the access key is a credential; share it only with trusted apps/devices. Provider login, logout, switching and key rotation are also available in **Provider settings**; the native dashboard's logout control is Android TV only.

Android starts its Rust server with `OPENSTREAM_EPG=true` even if imported TOML or the persisted EPG setting says false. The Rust server generates and serves EPG only when usable authenticated provider/channel data are available; `503` while the account-specific cache is not ready does not mean the Android EPG setting is off. Other platforms retain their own EPG settings.

**Login migration:** The earlier `org.jiotvgo.android` and current `org.opebstreamstv.android` application IDs have separate private storage. Installing the new app does not migrate the old app's private credentials. Use a supported, explicitly exported `store_v4.toml` backup from the old installation and **Import login store backup** in the new app when available; retain the old installation until migration is confirmed. A normal restart or in-place update of the **same application ID** preserves the private store. Uninstalling or clearing app data does not.

## Checks

Run `gradle testDebugUnitTest assembleRelease lint` after building the three Rust binaries. Automated unit tests cover playlist path validation, masked URL display, login-store schema checks, default EPG configuration, and startup preference persistence. Check the APK for `lib/<abi>/libopenstream_exec.so` for all three ABIs before sideloading; Gradle can assemble an APK even if the required Rust binaries are absent. A successful build does not by itself verify real OTP delivery or authenticated EPG generation.
